로켓보안 컨설팅 4단계

점검하고, 정책을 세우고, 증적을 쌓고, 조치합니다

조직의 준비 수준에 따라 필요한 단계를 정합니다. 웹 모의해킹을 함께 의뢰할 때는 대상 시스템, 허용 시간과 중단 연락처를 별도로 합의합니다. 웹 점검 범위 합의 예시

STEP 1 · 로켓점검

심사원 관점 사전점검

적용할 인증기준과 자료의 기준일을 정하고 조직·기술·개인정보 영역을 살펴봅니다.

  • 공개정보(OSINT) 기반 외부 노출 자산 확인
  • 서버·네트워크·웹 취약점 점검
  • 개인정보처리방침·흐름 분석
OUTPUT한줄결함 대장 · 우선순위(P1~P3) 조치 계획
STEP 2 · 로켓 정책수립

우리 회사 크기에 맞는 규정

대기업 템플릿을 복사하지 않습니다. 조직 규모와 실제 업무 흐름에 맞춘 정책·지침·절차를 작성합니다.

  • 정보보호·개인정보보호 정책 및 하위 지침
  • 개인정보처리방침 작성·개정
  • 위탁·제3자 제공 계약서 보안 조항
OUTPUT정책 문서 세트 · 경영진 승인용 요약본
STEP 3 · 로켓 증적

심사 때 바로 꺼내는 증적

접속기록 점검, 권한 검토, 교육 이력에 담당자와 확인 주기를 붙입니다. 누락된 기간은 따로 표시합니다.

  • 개인정보 접속기록 월간 점검 보고
  • 계정·권한 검토, 퇴직자 회수 확인
  • 증적 폴더 체계 · 인덱스 관리
OUTPUT월간 증적 패키지 · 심사 대응 체크리스트
STEP 4 · 로켓 조치

수정 결과를 확인합니다

네트워크 정책, 코드, 로그 수집 설정 중 변경이 필요한 위치를 정하고 재점검에서 비교할 증적을 합의합니다.

  • 방화벽·웹방화벽 정책 검토
  • 소스코드 보안점검
  • SIEM 로그 통합 · 보안관제 연계
OUTPUT조치 완료 보고 · 재점검 결과

개인정보 컨설팅

개인정보처리방침 평가 서비스

공개된 가입 화면과 처리방침을 먼저 대조합니다. 위탁사·내부 시스템의 처리 경로는 고객이 제공한 자료와 담당자 인터뷰로 확인합니다.

Input · 입력

  • 기업명, 서비스 도메인
  • (선택) 기존 처리방침·흐름표·흐름도 — 있으면 고도화·현행화
▼ 분석

Process · 처리

  • 공개 화면과 처리방침 열람
  • 처리방침 기재사항·가독성·접근성 평가
  • 합의한 수집·처리 경로 확인 — 가입 페이지, SNS 유입, 오프라인, 협력사, 위탁, 제3자 제공
  • 최신 법령 개정사항 대조

진행 예시

착수부터 조치 계획을 받기까지

아래는 한 서비스에 대한 일정 예시입니다. 실제 착수일과 납기는 대상 수, 자료 준비 상태, 인터뷰 가능 시간을 확인해 정합니다.

  1. D+0착수 · 공개정보 수집

    도메인·서브도메인·앱·SNS 채널을 공개 정보만으로 확인합니다. 서비스에 부하를 주는 스캔은 하지 않습니다.

  2. D+1인터뷰 30분

    담당자와 화상으로 조직·시스템·개인정보 업무를 확인합니다. 기존 문서가 있으면 이때 받습니다.

  3. D+2~3분석 · 모의심사

    ISMS-P 인증기준과 개인정보보호법을 기준으로 결함 후보를 도출하고 근거를 붙입니다.

  4. D+5보고 · 조치 계획

    한줄결함 대장과 우선순위 조치 계획을 경영진·실무자용 두 가지 버전으로 보고합니다.

  5. 이후정책 · 증적 · 조치

    필요한 단계만 골라 월 구독 또는 프로젝트로 이어갑니다.

담당자 역할

누가 무엇을 확인하나요?

착수 전에 점검 수행자, 자료 제공 담당자와 결과 승인자를 지정합니다. 담당자의 경력·자격과 이해충돌에 관한 확인이 필요하면 계약 전에 확인할 자료를 요청해 주세요.

  • 서비스 담당자 · 범위와 제외 항목 승인
  • 보안 담당자 · 제공 자료와 증적 확인
  • 점검 담당자 · 발견 근거와 한계 기록
  • 조치 담당자 · 변경 이력과 재확인 결과 검토

FAQ

자주 묻는 질문

범위·보고서·재점검·결제 전체 FAQ

ISMS-P 의무대상이 아닌데도 받을 수 있나요?

인증 준비, 서비스 보안 점검, 개인정보 처리 현황 확인 중 필요한 목표를 선택할 수 있습니다. 상담 시 현재 보유한 문서와 의뢰 범위를 알려주세요.

공개정보 수집(OSINT)이 우리 서비스에 영향을 주지 않나요?

공개된 페이지와 공개 DNS·인증서 정보만 읽는 수동 방식입니다. 로그인 시도, 인증번호 요청, 취약점 스캔, 대량 요청은 하지 않으며, 침투 성격의 점검은 서면 동의 후 별도 일정으로만 진행합니다.

이미 처리방침과 흐름도가 있습니다. 또 만들어야 하나요?

아닙니다. 기존 문서를 받아 최신 법령 개정과 실제 가입 화면·위탁 현황에 맞게 현행화합니다. 바뀐 부분만 표시한 개정 대조표를 함께 드립니다.

보고서와 자료는 어떻게 보관되나요?

자료 제공 전 수신자, 전달 경로, 보관 기간과 삭제 확인 방법을 서면으로 정합니다. 첫 상담 메일에는 원본 로그, 신분증, 계정 비밀번호를 첨부하지 마세요.

누가 수행하고 검토하는지 확인할 수 있나요?

계약 전 수행자와 검토자의 역할, 관련 경력 확인 방법과 이해충돌 여부를 문의할 수 있습니다. 최종 인증 판정은 해당 심사 절차에서 이뤄집니다.
