# 일일 개선 루틴 (Daily Improvement Routine)

소요 30~60분. 사람이 해도 되고 Claude Code 세션이 해도 된다. 매일 같은 순서로 한다.
자동 실행 시 프롬프트는 이 파일 §5를 그대로 쓴다.

## 1. 점검 (10분)

1. `improvement/DAILY_LOG.md` 마지막 기록을 읽고 "다음 할 일"을 확인한다.
2. `checklists/law-watch.md`에서 `[검증필요]` 또는 `[미조사]` 항목을 하나 고른다.
3. 개인정보보호위원회(pipc.go.kr) 보도자료·법령정보, 국가법령정보센터(law.go.kr)에서 그 항목을 확인한다. 요약 기사는 근거로 쓰지 않는다.
4. 확인한 원문을 `references/law/<ID>.md`에 저장(출처 URL·확인일). `law-watch.md` 상태를 갱신하고, 체크리스트의 같은 조문 `[검증필요]`를 제거한다.

## 2. 개선 1건 (20~30분)

`improvement/BACKLOG.md`에서 우선순위가 가장 높은 1건을 골라 끝낸다. 끝내지 못하면 쪼개서 일부만 끝내고 나머지를 백로그에 남긴다.
우선순위 규칙: P1 고객 전달 품질에 직접 영향 > P2 법령 정확성 > P3 자동화·편의.

## 3. 샘플 실행 (주 1회, 금요일)

공개된 기업 1곳(이미 처리방침 평가제 대상이 됐거나 뉴스에 나온 곳)을 골라 Phase 1~2만 수행한다. 결과는 `cases/_samples/`에 두고 고객 케이스와 섞지 않는다. 발견한 매뉴얼의 빈틈을 백로그에 추가한다.

## 4. 기록 (5분)

`improvement/DAILY_LOG.md`에 한 줄 추가:

```
| 2026-11-03 | 39 | L-02 §30의2 원문 검증 완료, 체크리스트 B 섹션 근거 갱신 | BACKLOG #3 OSINT 스크립트 crt.sh 파싱 |
```

`quality/scoring.md` §2 현재 점수를 갱신한다. 점수가 오르지 않은 날은 이유를 적는다.

변경은 git 브랜치에 커밋한다. 커밋 메시지: `privacy-assessment: <무엇을> (+N점)`.

## 5. 자동 실행용 프롬프트 (그대로 복사)

```
너는 로켓보안의 개인정보처리방침 평가 서비스 운영 담당이다.
저장소 happytoto/soc 의 services/privacy-policy-assessment/ 를 연다.
improvement/daily-routine.md 의 §1~§4 를 순서대로 수행한다.
- §1: law-watch.md 에서 [검증필요] 1건을 골라 law.go.kr 또는 pipc.go.kr 원문으로 검증하고 references/law/ 에 저장, 상태 갱신.
- §2: BACKLOG.md 최상위 1건을 완료.
- §4: DAILY_LOG.md 에 한 줄 기록, scoring.md 서비스 점수 갱신.
규칙: 고객 케이스 폴더(cases/)는 열지 않는다. 외부 사이트에 로그인·폼 제출·스캔을 하지 않는다. 법 조문을 추측해 쓰지 않는다. 모르면 "확인 필요"로 남긴다.
완료 후 변경 파일을 커밋하고 브랜치에 푸시한다. 보고는 표 한 개(오늘 변경 · 점수 변화 · 내일 할 일)로 끝낸다.
```

## 6. 중단 조건

- 같은 백로그 항목을 3일 연속 끝내지 못하면 항목을 다시 쪼개고 사용자에게 보고.
- 법령 원문 사이트 접근이 불가하면 §1을 건너뛰고 기록에 사유를 남긴다. 추측으로 채우지 않는다.
