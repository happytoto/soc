# 보안 수칙 — 열람 권한 · 보관 · 파기 · OSINT 안전

## 1. 열람 권한

| 자료 | 위치 | 열람 가능자 | 비고 |
|---|---|---|---|
| 고객 케이스 폴더 `cases/<케이스>/` | 로컬 작업 디스크(암호화 볼륨) + 사내 Drive 비공개 폴더 | 담당 컨설턴트, 검증자, 대표 | git 커밋 금지(`.gitignore`) |
| 전달본(PDF) | 고객 지정 채널 1곳 | 고객 담당자 | 비밀번호 PDF 또는 암호화 링크 |
| 매뉴얼·템플릿·체크리스트 | 저장소 `services/privacy-policy-assessment/` | 사내 전원 | 고객 식별 정보 포함 금지 |
| 샘플 케이스 `cases/_samples/` | 저장소 제외 | 사내 전원 | 공개 기업의 공개 정보만 |

- 케이스 폴더를 열 때마다 `cases/<케이스>/access-log.md`에 `일시 · 이름 · 목적`을 한 줄 남긴다.
- AI 세션(Claude Code 등)이 케이스를 열 때도 같은 로그를 남긴다. 일일 개선 루틴 세션은 `cases/`를 열지 않는다.

## 2. 보관·파기

| 단계 | 기준 |
|---|---|
| 작업 중 | 암호화된 디스크/볼륨에만 저장. 채팅·메일 본문·공개 저장소·임시 폴더에 복사 금지 |
| 전달 후 | 계약서에 정한 기간(기본 1년) 보관 후 파기. 원본 md·캡처·OSINT 결과 모두 포함 |
| 파기 | 복구 불가 삭제 후 `delivery/destruction-certificate.md` 작성, 고객에게 파기 확인서 발송 |
| 예외 | 고객 요청 또는 분쟁 대응 시 보관 연장 — 사유·승인자·기한 기록 |

## 3. OSINT 안전 수칙 — 장애·법적 문제 방지

**허용 (passive)**
- 공개 웹페이지를 사람이 보는 속도로 열람(초당 1요청 이하, 동시 1연결)
- DNS 조회, WHOIS, 인증서 투명성 로그(crt.sh), robots.txt·sitemap.xml 열람
- 앱스토어 공개 설명·개인정보 라벨 열람
- 검색엔진·뉴스·공시·인증 현황(isms.kisa.or.kr) 조회
- 브라우저 개발자 도구로 비로그인 상태의 네트워크 요청 관찰

**금지 (active) — 서면 동의와 별도 일정 없이는 절대 금지**
- 로그인 시도, 비밀번호 추측, 인증번호(SMS·이메일) 요청
- 회원가입·계정 생성·주문·결제·이벤트 응모·문의 폼 제출
- 포트 스캔, 취약점 스캐너(nmap -sV, nikto, nuclei, sqlmap 등), 디렉터리 브루트포스
- 대량·고속 요청, 크롤러로 전체 사이트 수집
- 관리자 페이지·숨김 경로 접근 시도, 파라미터 변조
- robots.txt에서 금지한 경로 열람

**spiderfoot 사용 시**
- passive 모듈만 지정 (`-m` 옵션으로 명시). `sfp_portscan_tcp`, `sfp_spider`(사이트 크롤링), 취약점 모듈은 비활성.
- 결과에 포함된 제3자 개인정보(직원 이메일 등)는 보고서에 원문 그대로 싣지 않고 "존재 여부"만 기재.

**장애 대응**
- 대상 사이트가 느려지거나 차단 응답(429·403)이 오면 즉시 중단하고 로그에 기록.
- 모든 수집은 `osint/00_collection-log.md`에 시각·대상·방법을 남겨 사후 소명 가능하게 한다.

## 4. 이해충돌

- 로켓보안이 컨설팅한 기업의 ISMS-P 인증심사에 로켓보안 소속 심사원은 참여하지 않는다. 계약서에 명시하고 `cases/<케이스>/00_intake.md`에 심사원 이름을 기록한다.
